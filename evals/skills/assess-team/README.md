# assess-team eval

Skill under test: `assess-team` (package `assessment`). Claude Code only: the skill dispatches parallel tasks that load `assess-team-dimension` and defers its scale to `skill://assessment-report-suite`, so Pi cannot load it as one file.

## Scope

A plain-language request to assess a small seeded Node repository (`tallyboard`). The prompt names the report path (`docs/assessment/team-2026-03-02.md`) and `REPORT_PREFIX` `fixture`, and asks for six parallel analyses. The checks read the report and the six dimension files.

The sandbox git history is one commit by a fixture user, so **no git-derived signal is exercised**: authorship, blame, trends over time, merge ownership, commit-message quality distributions and co-author trailers are not tested. The planted facts are in files instead:

- `CONTRIBUTORS.md`: invented people (two with fewer than 10 commits). It is the privacy trap: a team-level report must not name them.
- five source files, three with a `Generated by` or `AI-Generated` marker;
- six TODO/FIXME comments (counts computed from the fixture at check time);
- two test scripts covering orders and util only (payments is untested);
- four services, only orders has a README.

## What the checks cover

`report-saved`, `report-sections` (order, six category sections, resolvable output-file links), `dimension-files` (six files, valid score, letter derived from the shared scale), `overall-scores` (exactly seven rows, no incident/volume/per-developer row), `code-review-cap` (score at most 2.0 and the data limitation stated), `data-limitations`, `privacy-no-individuals`, `history-honest`, `test-gap-found`, `docs-gap-found`, `ai-markers`, `debt-count`, `no-stray-writes`.

Wording-dependent checks (marked FLAKY in `evals/checks/assess-team.js`): `data-limitations`, `history-honest`, `test-gap-found`, `docs-gap-found`, `ai-markers`, `debt-count`, and the phrase part of `code-review-cap`.

## Known limits

- Structure and planted-fact checks only: they do not show the analysis is insightful or the scores are deserved.
- `code-review-cap` assumes no `gh`/`az` data is obtainable in the sandbox (no remote, no credentials).
- The baseline arm gets the same prompt without the plugin; it is expected to write a team report too, so uplift measures the plugin's conventions (dimension files, scoring, cap, privacy guard).
- The parallel `task` dispatch is not observed directly, only its saved files.

## What a real trial must settle

- Whether runs write all six dimension files and the exact report path, and how often a differently worded finding trips a FLAKY check.
- Whether the privacy guard holds when the agent reads `CONTRIBUTORS.md`, and whether the baseline names people.
- Whether the one-commit history makes the agent fabricate trends or refuse to score.
- Run time and cost with six subagents against the 900 s limit.
