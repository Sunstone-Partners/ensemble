## 4. Deviations from the plan or TRD

1. **`packages/development/lib/ensemble-cli.js` was edited** (the plan's E11 step 1 described the
   launcher as `require('../lib/ensemble-cli.js');` only, and WP4's file list did not include the
   entry point). A bare require is inert: `ensemble-cli.js` ends with
   `if (require.main === module) { ... }`, and under the launcher `require.main` is
   `packages/full/bin/ensemble`, so nothing ran and `bin/ensemble --describe` exited 0 with empty
   stdout — `JSON.parse` threw `SyntaxError: Unexpected end of JSON input`. Instead of duplicating
   the envelope-printing and exit-code logic inside the launcher (two copies of the same
   process-boundary rule), the existing guard body was extracted into an exported
   `run(argv) { const { envelope, exitCode } = main(argv); if (envelope) process.stdout.write(...); process.exitCode = exitCode; return exitCode; }`,
   the guard now calls `run(process.argv.slice(2))`, and the launcher calls
   `require('../lib/ensemble-cli.js').run(process.argv.slice(2))`. Behaviour of `node
   lib/ensemble-cli.js ...` is unchanged (`tests/engine-registry.test.js` and
   `tests/engine-mount-parity.test.js` still pass), `main` stays pure with respect to the process
   (Constitution Rule 6), and TRD-004's "requires only builtins and relative bundle paths" still
   holds for the launcher.
2. **The pi-vendoring scenario asserts the require closure, not every file under
   `lib/engine/`.** `lib/engine/validate.js` is not reachable from `ensemble-cli.js` today (no
   module requires it yet; it is used by `tests/engine-envelope.test.js` directly), so the pi
   bundler — which vendors each entry file's require closure — correctly does not vendor it. The
   test therefore requires the seven modules the CLI actually reaches
   (`argv, describe, envelope, mount, registry, groups/trd, groups/tool`) to be present and
   byte-identical, and additionally fails on any vendored file with no source counterpart (the
   stale-vendor shape `toolchain-vendor-sync.test.js` guards for). Asserting on all of
   `lib/engine/**` would have demanded that the bundler vendor dead code.
3. **No commit, no PR.** Per the plan's stated overrides, this phase leaves everything
   uncommitted; Foreman commits and opens the PR.
