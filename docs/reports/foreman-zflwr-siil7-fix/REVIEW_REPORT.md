## Fixed

### 1. `packages/permitter/README.md` — the package's documented behaviour was not reconciled with the diff

- **What was wrong**: the diff adds two user-visible refusals (`shell invocation not supported`, `shell -c behind a wrapper not supported`), adds `ZDOTDIR` to `DANGEROUS_ASSIGNMENT_VARS`, and expands a shell wrapper from `bash`/`sh` to every supported shell. The README's "Parse Errors" table is this package's list of the messages the hook can print, and its `normalizeSegment()` reference lists the conditions under which the function throws; neither mentioned any of it. The "bash -c with a command the parser skips is not supported" row also still named only `bash -c` / `sh -c`, so `zsh -c "unset FOO; npm test"` was documented as a form the parser accepts.
- **What changed** (`packages/permitter/README.md:744`, `:753`, `:754`, `:357`): `ZDOTDIR` added to the "Dangerous variable assignment not supported: NAME" row; two rows added for the new refusals, with the causes the code actually has (an option the parser cannot read — an unknown option, a startup file, an option whose value sits inside a cluster — and a shell `-c` behind a prefix); the "skips" row now names every shell the parser expands (`bash`, `sh`, `zsh`, `dash`, `ksh`, `ash`, `mksh`); the `normalizeSegment()` "Throws" line now lists `ZDOTDIR` and the three shell refusals, including `shell -c with more than one inner command is not supported`, which is reachable only through that exported function.
- **Evidence**: `bash --unknown-option -c "npm test"`, `bash --rcfile ./payload.sh -ic "git status"`, `bash -eo pipefail -c "npm test"` and `bash --login -c "npm test"` throw `shell invocation not supported`; `sudo bash -c "npm test"`, `env bash -c "npm test"`, `timeout 5 bash -c "npm test"`, `time bash -c "npm test"`, `nice bash -c "npm test"` and `nohup bash -c "npm test"` throw `shell -c behind a wrapper not supported`; `zsh -c "unset FOO; npm test"` throws the "skips" message; `ZDOTDIR=./payload zsh -c "npm test"` throws `Dangerous variable assignment not supported: ZDOTDIR`.

### 2. `packages/permitter/lib/command-parser.js` — the refusal message this diff introduces named one shell

- **What was wrong**: the diff raises `bash -c with more than one inner command is not supported` from `normalizeSegment()`, but the diff also makes that function expand `zsh`, `dash`, `ksh`, `ash` and `mksh` wrappers, so the message named one shell for a rule that applies to all of them. The message was introduced by this diff and has not shipped, so it could still be corrected.
- **What changed** (`packages/permitter/lib/command-parser.js:907`): the message is now `shell -c with more than one inner command is not supported`. The two assertions that matched it in `packages/permitter/tests/security.test.js` (`:1592`, `:1841`) were tightened to the full new text so the old wording can no longer pass. The pre-existing message `bash -c with a command the parser skips is not supported` was left alone: it already applied to `sh` on `dev`, so this diff did not make it inaccurate and renaming a shipped message is outside this run's scope.
- **Evidence**: failing first — the tightened assertions failed with `Received message: "bash -c with more than one inner command is not supported"`; green after the rename (`cd packages/permitter && npx jest tests/security.test.js -t "inner segment"` → 50 passed, 502 skipped, exit 0).

### 3. `packages/permitter/CHANGELOG.md` — a new Security bullet described a refusal the code does not make

- **What was wrong**: the bullet added by this diff says an option form that is not a flag (`bash +e -c "..."`, `bash -O extglob -c "..."`) "defer[s] to the permission dialog". The parser reads `+e` as the option it is and `-O extglob` as an option with a value, so the command string after `-c` is expanded and judged like any other command: `bash +e -c "npm test"` parses to `[{executable:'npm',args:'test'}]` and is auto-allowed under `Bash(npm test:*)`. Only the same shell behind a prefix is refused (`env bash +e -c "npm test"` → `shell -c behind a wrapper not supported`).
- **What changed** (`packages/permitter/CHANGELOG.md:29`): the bullet now says that an unknown option and a startup file defer to the permission dialog, and that an option that turns a flag off and an option with a value are read as the options they are — the command string after `-c` is expanded and judged like any other command, so the shell alone does not approve it — while the same shell behind a prefix defers to the permission dialog.

### 4. `packages/permitter/CHANGELOG.md` — "a path in a system directory" was wider than what the code trusts

- **What was wrong**: the bullet added by this diff says a shell is trusted when it is "a bare name or a path in a system directory". The code trusts only `/bin`, `/usr/bin`, `/sbin` and `/usr/sbin` (`TRUSTED_SHELL_DIRECTORIES`): `/usr/local/bin/bash -c "git status"` is not expanded and stays a single segment.
- **What changed** (`packages/permitter/CHANGELOG.md:30`): the bullet now names the four directories.

After the fixes, the range was re-read (`git diff dev`, working tree included): the renamed message is shell-generic like the code path that raises it, the README rows list exactly the refusal sites of `packages/permitter/lib/command-parser.js:854`, `:857`, `:868`, `:871`, `:883`, `:907` and `:976`, and the two rewritten changelog bullets match the behaviour reproduced by the probes above.
