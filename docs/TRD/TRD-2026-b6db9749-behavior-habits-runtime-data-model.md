## Overview

This work adds no database. The new state comes in three kinds:

1. **Two event payloads** in the closed catalog:
   - `artifact.changed`, which is new;
   - `release.completed`, which exists; this work gives it a defined payload.
2. **Session-local, in-memory state**, lost on restart by design (Rule 4, NFR-006):
   - artifact snapshots and digests;
   - the release tags already reported;
   - the bounded event backlog;
   - notification delivery states.
3. **Checkout-local policy files** under `.ensemble/state/`, gitignored (REQ-031, REQ-029). The notification journal under `.ensemble/` is also checkout-local (NFR-004).

   These files are local configuration-like state. They have no scheduling, retry, recovery or cross-machine semantics.

## Relationships

- An `artifact.changed` event updates exactly one `ArtifactSnapshot`. `artifact.compare` reads the previous snapshot and the current one.
- A `NotificationRecord` references one event, by `eventId`, and one behavior.
- A `PackageQuarantineRecord` excludes its package from discovery. `proposal-store.ts` refuses evidence whose originating behavior is quarantined (AC-020-3).
- An `AuthoringRecord` is keyed by the same behavior id that discovery reports.

## Data Ownership

| Data | Owner | Writer | Readers |
|---|---|---|---|
| Event payloads | `agent-core` catalog | the adapters, via `normalizeEvent` | matcher, workflows |
| Snapshots, backlog, delivery state | the running session | `file-source-adapter.ts`, `local-event-matcher.ts`, `notification-state.ts` | the same session only |
| Quarantine record | the local checkout (operator) | `package-quarantine.ts` | discovery, status, operator |
| Authoring record | the local checkout | `package-discovery.ts`, `fixture-conformance.ts` | `runtime-status.ts` |
| Notification journal | the local checkout | `notification-state.ts` via `logRuntime` | operator, PM/QA via the status file |

## Migration/Backfill Notes

- No existing data is migrated.
- `.ensemble/state/` is new. Add it to `.gitignore` in TRD-017; it is **not** ignored today.
- A missing file means "no records". Do not backfill authoring history: packages that already exist get `startedAt` at their next discovery, and the report marks them as pre-instrumentation.

## Validation Rules

- `path` must resolve inside the repository root. Anything else fails validation (AC-001-2).
- The `tag` pattern comes from the trigger predicate, and only matching tags emit events.
- Checkout-local files must carry `schema_version`. An unknown version or malformed JSON is a named diagnostic.
  - For quarantine, a malformed file **keeps** every listed package quarantined (fail closed).
  - For authoring, a malformed file disables the metric and never blocks activation.
- Timestamps are ISO-8601 UTC.
- The backlog bound is a positive integer, set in configuration.

## Privacy/Security Notes

- Snapshots hold artifact content in memory only, bounded by file size, and never write it to disk.
- The notification journal stores evidence *references* and digests, not raw test output. Any quoted text is size-capped and redacted (TRD-007).
- The quarantine `reason` is generated by Ensemble from the grant check, not copied from package text, so a package cannot plant text in it.
